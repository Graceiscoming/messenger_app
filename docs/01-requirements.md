# 01 – Requirements และ Use Case Specification

## 1. ขอบเขตระบบ
Messenger App คือระบบแชทที่ให้ผู้ใช้สมัครสมาชิก เพิ่มเพื่อน และส่งข้อความหากันแบบ realtime ทั้งแชทส่วนตัวและกลุ่ม

## 3. Non-functional Requirements
- **Security:** รหัสผ่านต้องแฮช, ทุก API (ยกเว้น register/login) ต้องมี JWT, ตรวจสิทธิ์สมาชิกห้องทุกครั้งก่อนอ่าน/เขียนข้อความ, จำกัดชนิดและขนาดไฟล์ (jpeg/png/webp/gif ≤ 5 MB), ป้องกัน XSS โดยแสดงข้อความเป็น text
- **Performance:** โหลดประวัติด้วย cursor pagination (`beforeId`), index `(ConversationId, Id DESC)`
- **Reliability:** ส่งข้อความผ่าน REST เพื่อให้ได้ response ยืนยันและบันทึกลง DB ก่อน แล้วค่อย broadcast ผ่าน SignalR
- **Maintainability:** แยกเลเยอร์ชัดเจน (Presentation / Domain / Data Access)
- **Portability:** รันทั้งระบบด้วย `docker compose up`

## 4. Business Rules
1. `Username` ไม่ซ้ำ (case-insensitive), 3–20 ตัว (a-z, 0-9, _)
2. ส่งข้อความ 1:1 ได้เฉพาะ **เพื่อนที่ยอมรับแล้ว (Accepted)** และไม่มีการบล็อกฝ่ายใด
3. ระหว่างผู้ใช้สองคนมี Friendship ได้เพียง 1 record (ไม่ว่าใครเป็นผู้ส่งคำขอ)
4. ระหว่างผู้ใช้สองคนมี Direct conversation ได้ 1 ห้อง (`DirectKey = minId_maxId`)
5. เมื่อลบเพื่อน ห้องแชทและประวัติยังอยู่ แต่ส่งข้อความใหม่ไม่ได้ (read-only)
6. กลุ่มต้องมีสมาชิกอย่างน้อย 2 คน, ผู้สร้างเป็น `Owner`; เพิ่มสมาชิกได้เฉพาะเพื่อนของผู้เพิ่ม
7. Owner/Admin เพิ่ม-ลบสมาชิกได้; Owner ออกกลุ่มต้องโอนสิทธิ์ก่อน (หรือโอนให้สมาชิกที่เก่าที่สุดอัตโนมัติ)
8. Unsend ได้เฉพาะ **ข้อความของตนเอง** ภายใน **24 ชั่วโมง** (ค่า config) และยังไม่ถูก unsend
9. ข้อความที่ unsend แล้วจะไม่ส่งเนื้อหา/ไฟล์กลับ client (แสดง "ข้อความนี้ถูกยกเลิกการส่ง") และลบไฟล์รูปออกจาก storage
10. ข้อความ 1–2000 ตัวอักษร; ข้อความรูปภาพ caption ได้ไม่เกิน 500 ตัว
11. Read receipt: `LastReadMessageId` ของสมาชิกแต่ละคนในห้อง

## 5. Actors
| Actor | คำอธิบาย |
| :--- | :--- |
| Guest | ผู้ที่ยังไม่ล็อกอิน (สมัคร/ล็อกอินได้) |
| User | สมาชิกที่ล็อกอินแล้ว |
| Group Owner/Admin | User ที่มีบทบาทจัดการกลุ่ม (สืบทอดจาก User) |
| System | งานอัตโนมัติ เช่น ลบไฟล์ของข้อความที่ unsend, ล้าง refresh token หมดอายุ |

## 6. Use Case Specification (ข้อความ)

### UC-01 สมัครสมาชิก
- **Actor:** Guest
- **Pre:** ไม่มี
- **Main flow:** 1) กรอก username, display name, password 2) ระบบตรวจรูปแบบและความซ้ำ 3) แฮชรหัสผ่านแล้วบันทึก 4) คืน access/refresh token
- **Alt:** username ซ้ำ → 409 Conflict
- **Post:** มี User ใหม่

### UC-02 เข้าสู่ระบบ / ออกจากระบบ
- **Main flow:** กรอก username+password → ตรวจสอบ → ออก JWT (อายุ 15 นาที) + refresh token (7 วัน) → เชื่อม SignalR
- **Alt:** รหัสผิด → 401; ล็อกอินผิด 5 ครั้งติด → ล็อกชั่วคราว 5 นาที
- **ออกจากระบบ:** เพิกถอน refresh token

### UC-03 ค้นหาผู้ใช้และส่งคำขอเป็นเพื่อน
- **Pre:** ล็อกอินแล้ว
- **Main flow:** 1) ค้นหา username 2) กด "เพิ่มเพื่อน" 3) ระบบสร้าง Friendship สถานะ `Pending` 4) แจ้งผู้รับแบบ realtime
- **Alt:** เป็นเพื่อนกันแล้ว/มีคำขออยู่/ถูกบล็อก → 409/403; ส่งให้ตัวเอง → 400
- **Alt:** ถ้าอีกฝ่ายส่งคำขอมาก่อนแล้ว → ระบบยอมรับให้อัตโนมัติ

### UC-04 ตอบรับ/ปฏิเสธคำขอเป็นเพื่อน
- **Pre:** มีคำขอ Pending ที่ส่งถึงตน
- **Main flow:** เลือก Accept → สถานะ `Accepted`, สร้าง Direct conversation (ถ้ายังไม่มี), แจ้งผู้ส่ง | เลือก Decline → ลบ record

### UC-05 ดู/ลบเพื่อน
- ดูรายชื่อเพื่อน (พร้อมสถานะออนไลน์) ค้นหาในรายชื่อได้; ลบเพื่อน → ลบ Friendship, ห้อง 1:1 เป็น read-only

### UC-06 ส่งข้อความ (ข้อความ/รูป/Sticker)
- **Pre:** เป็นสมาชิกห้อง และ (ถ้า 1:1) ยังเป็นเพื่อนกัน
- **Main flow:** 1) พิมพ์ข้อความ (หรือเลือกรูป/Sticker) 2) client เรียก `POST /conversations/{id}/messages` (รูปต้องอัปโหลดก่อนได้ `attachmentId`) 3) ระบบตรวจสิทธิ์+validate 4) บันทึก 5) broadcast `MessageReceived` ให้สมาชิกที่ออนไลน์ 6) ตอบ 201 พร้อม message
- **Alt:** ไม่ใช่เพื่อน/ถูกบล็อก → 403; ไฟล์ผิดชนิด/ใหญ่เกิน → 400/413

### UC-07 ดูห้องแชทและประวัติข้อความ
- รายการห้องเรียงตามข้อความล่าสุด + unread count; เปิดห้องแล้วโหลดข้อความล่าสุด 30 รายการ เลื่อนขึ้นเพื่อโหลดเพิ่ม (cursor) แล้วระบบอัปเดต `LastReadMessageId` และ broadcast `MessageRead`

### UC-08 Unsend ข้อความ
- **Pre:** เป็นผู้ส่ง, ภายในเวลาที่กำหนด
- **Main flow:** เลือกข้อความ → "ยกเลิกการส่ง" → ระบบตั้ง `UnsentAt`, ล้างเนื้อหา, ลบไฟล์แนบ → broadcast `MessageUnsent` → ทุก client แสดง placeholder
- **Alt:** ไม่ใช่เจ้าของ → 403; เลยเวลา → 409

### UC-09 สร้างและจัดการกลุ่ม
- สร้างกลุ่ม (ชื่อ + เลือกเพื่อน ≥ 1 คน), เปลี่ยนชื่อ/รูปกลุ่ม, เพิ่ม/ลบสมาชิก, แต่งตั้ง Admin, ออกจากกลุ่ม; ทุกการเปลี่ยนแปลงสร้าง System message (เช่น "A เพิ่ม B เข้ากลุ่ม")

### UC-10 บล็อกผู้ใช้
- บล็อกแล้วอีกฝ่ายส่งข้อความ/คำขอเพื่อนไม่ได้; ถ้าเป็นเพื่อนกันจะถูกลบความเป็นเพื่อน

### UC-11 แก้ไขโปรไฟล์
- แก้ display name, status message, อัปโหลดรูปโปรไฟล์

### UC-12 แสดงสถานะ (Presence/Typing)
- SignalR connection/disconnect อัปเดตออนไลน์; client ส่ง `Typing` ไปยังสมาชิกห้อง (ไม่เก็บลง DB)
